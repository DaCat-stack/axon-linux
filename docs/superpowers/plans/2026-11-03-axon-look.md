# AXON Look Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** AXON-branded boot splash, login screen, three desktop presets with a first-run chooser, and a branded Calamares installer in the AXON Linux ISO.

**Architecture:** Everything ships as files under `profile/airootfs/` (overlaid on archiso `releng` by `build.sh`), plus an AUR stage in CI that builds Calamares into a local pacman repo before `mkarchiso`. Generated images come from scripts in `branding/` and are committed. Verification: `tests/static.sh` (runs on Mac and in CI), QML lint + SDDM greeter screenshot in CI, and a QEMU boot screenshot of the finished ISO in CI.

**Tech Stack:** archiso, Plymouth (script module), SDDM (Qt6 QML), KDE Plasma 6 look-and-feel packages (layout JS), Python 3 + PySide6 (welcome app), Calamares (AUR), GitHub Actions, QEMU, Pillow (image generation, Mac side).

**Spec:** `docs/superpowers/specs/2026-11-03-axon-look-design.md`

## Global Constraints

- Colors: boot bg `#07090d`, wallpaper bg `#0a0f1c`, teal `#28a8a8`, blue `#2f86f0`.
- Logo source: `assets/axon-logo.png`, parts `assets/logo-blue.png` + `assets/logo-white.png` (same 1024×1024 canvas). Never stretch: always scale uniformly.
- All UI copy in Russian, exact strings from the spec/mockups (`.superpowers/brainstorm/15725-1793703572/content/*.html`).
- No third-party Plasma widgets/KWin scripts; only stock Plasma 6 applets.
- Never write into users' `~/.config` except via the welcome app on explicit click; system defaults live in `/etc/xdg`, `/usr/share`.
- Packages from official Arch repos; only exception is `calamares` (built from AUR in CI).
- Nothing may require network on first boot.
- Theme / package names: Plymouth `axon`, SDDM `axon`, look-and-feel `org.axon.desktop.a|b|c`, wallpaper package `AXON`, welcome app `axon-welcome`, Calamares branding `axon`.

## Review Focus

- **4K / non-1080p screens:** Plymouth logo and SDDM card must scale from screen height (logo ≈ 17.5% of height), not fixed pixels → Task 3 static test asserts the script reads `Window.GetHeight()`; Task 4 screenshot at 3840×2160 in addition to 1920×1080.
- **Multiple monitors at login:** card only on the primary screen, others show wallpaper only → Task 4 `Main.qml` gates the card on `screenModel`/primary; asserted by grep in `tests/static.sh`.
- **Password typed in RU layout:** layout indicator visible and clickable on the login card's top bar → Task 4 screenshot check lists the indicator.
- **Welcome app re-runs:** it autostarts only until the owner picks a style or clicks «Позже» (both mark done); afterwards it opens only from the menu. Unit tests in Task 6 cover `should_autostart` before/after marker.
- **Windows on the disk:** installer defaults to «рядом с Windows» when Windows is found, and GRUB lists Windows → Task 7 static test greps `GRUB_DISABLE_OS_PROBER=false` and partition module `defaultPartitionTableType`/`initialPartitioningChoice: alongside`.
