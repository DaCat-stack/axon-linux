# AXON Linux — репозиторий обновлений и Магазин AXON

Дата: 2026-11-03. Статус: черновик, ждёт одобрения владельца.

## Зачем
Владелец хочет, чтобы система была **надёжной и обновлялась**. Его прошлая боль на
Linux — не обновления, а кастомизация: встроенный магазин KDE («Загрузить новые…»,
store.kde.org) не загружался, а файлы с сайта магазина открывались в том же
неработающем окне и ничего не ставилось.

Сейчас всё своё (оформление, окно приветствия, настройки) лежит в ISO россыпью файлов:
после установки оно никогда не обновится. Нужно:
1. свой репозиторий пакетов AXON, через который установленные системы получают обновления;
2. **Магазин AXON** — своя витрина оформления, где всё проверено и точно работает.

## Цели
1. Репозиторий pacman `axon`: всё своё — пакетами, подписанными ключом AXON; обновления
   приходят обычным обновлением системы (Discover / `pacman -Syu`).
2. Проверенная подборка оформления (список ниже) — пакетами в том же репозитории.
3. Приложение «Магазин AXON»: карточки с превью, установка и применение в один клик,
   откат «как было».
4. Защита от поломок после обновлений KDE: каждая вещь из подборки регулярно проверяется
   на свежем Plasma из Arch; сломанная — скрывается в Магазине до починки.
5. Встроенный магазин KDE в AXON работает: есть всё нужное для «Загрузить новые…»,
   ссылки `ocs://` с сайта открываются правильно.

## Не цели
- Свои форки чужих тем; правка чужого оформления сверх упаковки.
- Платный контент. Сам Wallpaper Engine (платная программа в Steam) — не наш; мы ставим
  только бесплатный плагин KDE, который показывает обои из уже купленного Wallpaper Engine.
- Свой экран входа и загрузки в подборке: у AXON свои фирменные, сторонние не берём.

## Анти-цели (провал, даже если «работает»)
- Вещь из Магазина ломает панель или рабочий стол после обновления и это доходит до пользователя без предупреждения.
- Для установки чего-либо нужен терминал.
- Обновление AXON перезаписывает личные настройки пользователя (`~/.config`).
- В репозиторий может попасть неподписанный пакет, или pacman примет пакет с чужой подписью.
- Обновления перестают приходить молча (истёк ключ, умер сервер) — пользователь об этом не знает.

## Как устроено (решения)
### Пакеты AXON
- `axon-keyring` — публичный ключ AXON для pacman.
- `axon-branding` — обои, Plymouth, SDDM, пресеты A/B/C, системные настройки `/etc/xdg`
  (переезд из россыпи файлов в `profile/airootfs`).
- `axon-welcome` — окно «Выбери свой стиль».
- `axon-store` — Магазин AXON.
- `axon-store-<вещь>` — по пакету на каждую вещь подборки (например `axon-store-sweet`),
  собирается из исходников автора с зафиксированной версией и контрольной суммой.
- Live-только (установщик, ярлык, автовход) остаются файлами ISO и в пакеты не идут.
- Пакеты AXON никогда не пишут в `/home`; системные значения — только в `/etc/xdg`, `/usr/share`.

### Репозиторий
- Хостинг — **открытый вопрос (см. ниже)**; pacman ходит по HTTPS без логина, значит
  файлы должны быть доступны публично.
- Два канала: `axon-testing` (сюда CI кладёт всё новое) и `axon` (стабильный). В
  стабильный пакет переносится только после зелёных проверок; ISO и установленные
  системы смотрят в `axon`.
- Подпись: каждый пакет и база подписываются ключом AXON. *(моё решение)* Главный ключ
  хранится офлайн у владельца (на маке, в Связке ключей); в GitHub Actions лежит только
  подключ для подписи, который можно отозвать и заменить обновлением `axon-keyring`; в `pacman.conf` для `[axon]` — `SigLevel = Required DatabaseRequired`.
- `[axon]` стоит в `pacman.conf` перед `[core]`, чтобы наши пакеты имели приоритет только
  для своих имён (имена `axon-*` не пересекаются с Arch).

### Сборка и проверки (CI)
- Каталог `packages/<имя>/PKGBUILD` в репозитории; CI собирает изменённые, подписывает,
  выкладывает в `axon-testing`.
- Проверка совместимости — **каждую ночь** и при каждом изменении: чистый контейнер Arch
  с текущим Plasma → установить каждый `axon-store-*` → проверки по типу:
  глобальные темы/плазма-темы/виджеты — `kpackagetool6` видит пакет, QML без ошибок
  (`qmllint`), виджет открывается в `plasmoidviewer` под Xvfb без ошибок в логе и даёт скриншот;
  эффекты/скрипты KWin — метаданные валидны, JS/QML без ошибок; иконки/курсоры — индекс темы валиден.
- Итог пишется в `compat.json` (вещь → ok / сломано + версия Plasma), публикуется рядом с репозиторием.
  `compat.json` описывает **стабильный** канал `axon` — то, что реально стоит у пользователя. *(моё решение)*
- Перенос из `axon-testing` в `axon` — **по пакету**: сломанный чужой виджет не задерживает
  исправление `axon-branding` или ключа. *(моё решение)*
- **Опережающая проверка** *(моё решение)*: Arch выпускает новый Plasma/Qt сам, мимо нас, а
  придерживать пакеты Arch нельзя (частичные обновления ломают Arch сильнее). Поэтому ночная
  проверка гоняется дважды: на текущем Plasma из `[extra]` и на будущем из `[kde-unstable]` /
  `[extra-testing]`. Поломку видно за дни–недели до того, как обновление придёт пользователю:
  есть время починить или заранее скрыть вещь. Если поломка всё же дошла — вещь скрывается,
  Магазин предлагает откат (см. ниже). Компилируемые вещи (плагин Wallpaper Engine) пересобираются
  при каждом обновлении Qt в Arch.
- Что-то сломалось → оповещение владельцу в Discord (через уже существующий релей на сайте AXON).

### Магазин AXON (приложение)
- PySide6 + QML, как окно приветствия; тот же тёмный стиль AXON.
- Разделы: Темы, Иконки, Курсоры, Эффекты, Окна, Виджеты, Мониторинг, Обои, Терминал.
- Карточка: превью, название, автор, «Установить» → «Применить» → «Удалить».
  Установка — через pacman с запросом пароля (polkit), без терминала.
  Применение — штатными командами Plasma (`plasma-apply-lookandfeel`, `-colorscheme`,
  `-cursortheme`, `-desktoptheme`, `-wallpaperimage`, смена иконок, включение эффекта KWin);
  виджеты — кнопка «Добавить на панель».
- Перед первым «Применить» Магазин запоминает текущие настройки оформления;
  «Вернуть как было» — восстанавливает их.
- Магазин читает `compat.json`: сломанные вещи не показываются для установки; если
  сломанная уже установлена и применена — Магазин предлагает откатить её.
- Без интернета Магазин показывает установленное и честно пишет, что каталог недоступен.
- Открывается из меню и из окна приветствия.

### «Обновления перестали приходить» *(моё решение)*
- Таймер в `axon-branding` раз в день проверяет дату базы `axon`; если она старше 14 дней
  или подпись не проходит — уведомление на рабочем столе «Обновления AXON не приходят» и
  плашка в Магазине.

### Существующие установки
- Установленных систем со старой «россыпью файлов» нет (ISO ещё ни разу не ставился),
  миграция не нужна — только новые ISO.

### Встроенный магазин KDE
- Убедиться, что в AXON стоят пакеты, нужные «Загрузить новые…», и что ссылки `ocs://`
  открывают установщик KNewStuff. Проверка в CI: обработчик `x-scheme-handler/ocs` зарегистрирован.
- Если сервер store.kde.org не отвечает — это вне нашего контроля; Магазин AXON — наш надёжный путь.

## Ограничения
- Сборка — GitHub Actions (у владельца M1 Mac); репозиторий GitHub приватный.
- ISO уже собирается с оформлением в ветке `axon-look`; эта работа строится поверх неё.
- Пакеты Arch остаются из официальных зеркал; наш репозиторий их не подменяет.

## Открытые вопросы (решает владелец)
1. **Где хостить репозиторий пакетов**, если GitHub-репозиторий проекта приватный:
   (а) отдельный публичный GitHub-репозиторий только для пакетов (Releases; два релиза —
   `axon` и `axon-testing`), или
   (б) сайт axon-project.ru на Beget (папка `/linux/repo/`; загрузка по FTP через
   временную папку и переименование, чтобы pacman не увидел половину обновления).
   В обоих случаях готовые пакеты чужих тем лежат публично — берём только вещи, чья
   лицензия разрешает распространять собранное (GPL/CC и т. п.).
2. **Откат системы после неудачного обновления** (снимки btrfs + пункт «вернуться к
   состоянию до обновления» в меню загрузки). Сейчас по умолчанию ext4 без снимков.
